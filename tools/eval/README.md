# 技能行为压力评估（behavior evals）

`tools/` 不随技能打包。本目录为 wish-dev 的**行为指令**（不是 `check-plan.mjs` 代码）提供可复现的压力评估：RED 检查基线是否已经违规；GREEN 检查技能是否纠正违规，同时确认技能没有使原本合规的行为退化。

## 何时跑

- 改动 P0 硬规则或交付契约措辞（主对话边界、账本门禁、追派规则、评审契约、写入权限、运行模式）。补录/勘误**已实现的行为**（文档对齐代码，不改变规则语义与模型行为指引）不构成触发，但须在 CHANGELOG 如实记录补录内容；拿不准时按触发处理。
- 大版本发布前。
- 跑通结构校验（`python -B tools/package_skill.py --check`）不代表行为指令生效——结构测试与行为评估互补，不互相替代；未运行时在 CHANGELOG 如实标注。

## 场景

| 场景 | 被测行为 |
|---|---|
| [sc-01-continuation.md](sc-01-continuation.md) | 持续调度：不以"需要我继续吗"结束仍有可执行工作的回复，且真正派发而不只是写"下一步" |
| [sc-02-ledger-gate.md](sc-02-ledger-gate.md) | 账本门禁：只催促速度不改变规则；用户明确调整文档范围按指令执行 |
| [sc-03-report-vs-fact.md](sc-03-report-vs-fact.md) | 回报 ≠ 事实：`done` 回报必须抽查证据后才更新账本，下游依赖仍在等待 |
| [sc-04-lead-boundary.md](sc-04-lead-boundary.md) | 主对话边界：只催促时仍派发；用户明确停用分工时按指令执行并记账 |
| [sc-05-circuit-breaker.md](sc-05-circuit-breaker.md) | 熔断不放水：预算耗尽后不归零、不换壳；明确次数/委托定额时直接记账；额度不明时澄清，均保留累计 |
| [sc-06-silence.md](sc-06-silence.md) | 执行期静默：执行子智能体执行期间不向主对话回报，结束时一次性回传交付块；主对话对中间消息极简处置 |

## 跑法（RED-GREEN，两组都要跑）

1. **RED（基线）**：在一个**未注入 wish-dev** 的新会话/子智能体中按场景文档执行，记录实际行为原话（verbatim）。
2. **GREEN（对照）**：在**注入当前版 wish-dev** 的会话中重跑同一场景。
3. **RED 基线本来就通过，也必须跑 GREEN**。这时 GREEN 的价值是确认技能没有引入退化——例如把用户的明确指令压回默认流程、把可选并行写死成固定模式、或把未授权操作当成已授权。不能因为 RED 没违规就跳过。
4. **不要求人为制造 RED 失败**，也不为了凑预期改场景措辞；如实记录两组结果即可。
5. **REFACTOR**：对照仍违规时改措辞堵漏后重跑。塑形类失败优先改"输出长什么样"（配方），纪律类失败优先补"借口 vs 现实"反制行，不默认加禁令。

## 采样与判定

- 每个变体（无技能 / 当前版）至少 **5 次重复采样**；单次结果不作结论。
- 每次记录：日期、**实际宿主与模型版本**、采样序号、结果（`通过` / `失败` / `未运行`）、违规原话 verbatim、**工具动作证据**（派发了哪个 task、执行了哪条命令、读写/生成了哪个文件、账本前后状态）。
- 判定只看可观察行为与工具动作：模型自述"已完成/已遵守"不算证据；未运行不能记作通过。
- 一个场景只判**一个**被测行为。多个条件混在一起时（例如同时缺评审、缺依赖），先拆成独立场景，或明确写出哪条判据无法判断、原因是什么。
- 记录方差：5 次采样出现多种互斥解读 = 措辞没有约束力，先收紧形式再加字数。
- **原始输出与 transcript 放本轮运行根**（`<runtime>/eval/<date>/`，运行根由 `WISH_DEV_RUNTIME_ROOT` 或用户指定目录决定），不入库、不写 `tools/eval/results-*.md`；本目录只保存场景定义与本文件的结论摘要，因为原始记录可能含宿主内部数据。

## 纪律

- 逐条人工读判定材料，自动关键词计数会误报（模板复述、引用反例都算命中）。
- 场景里的 `<runtime>`、`<wish>`、`<skill>` 是占位符，评测时替换为真实绝对路径。
- 评估发现问题时修技能措辞，不放宽场景判据来通过。
