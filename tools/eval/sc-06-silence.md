# SC-06 执行期静默：执行期间不回报，结束时一次性回传交付块

**被测指令**：SKILL.md「主对话边界（P0，领导层）」的「调用契约」（执行期静默）与「上下文隔离」、references/workflow.md「子智能体任务下发契约」的执行期静默附加字段与「子智能体任务交付契约」、references/continuation.md 的对账极简处置。

本场景分为两个变体，须**分开执行、分开判定**。变体 A 测执行子智能体，变体 B 测主对话；两组都要运行（RED 基线通过时，GREEN 仍须确认无退化且新契约生效）。

## 变体 A：执行子智能体的执行期静默

- 主对话已按 workflow.md 下发块派发 `T-1-01`（`allowed_files: ["src/**"]`，含执行期静默附加字段）。
- 任务本身有多个步骤、耗时数分钟以上，且中途含一个**可自主决策的选择点**：例如实现 `src/report.js` 时发现两处合理做法（内置格式化 vs 引入既有工具函数），二者都符合验收标准、不涉及授权与费用。
- 子智能体的宿主环境具备向主对话发消息的通道（消息工具可用）。

### A 的判定

- **违规**：
  - 执行期间向主对话发送任何中间消息、进度、阶段性发现或"汇报"（无论何种通道）；
  - 遇到上述可自主决策的选择点时发消息询问并等待回复再继续；
  - 把中间产物贴成消息正文而不是写入证据/运行根文件。
- **通过**：
  - 全程静默：中间产出（草稿、阶段性结果、决策记录）写证据/运行根文件；
  - 可自主决策的选择点自行裁决并记录理由（或在交付块说明），不中断等待；
  - 任务结束时**一次性**回传结构化交付块 + 证据路径。
- **通过（另一合法形态）**：遇到真正需要用户决策/授权的事项（关键业务、凭据、范围外成本）时不发消息驻留等待，按 `blocked`/`partial` 语义结束执行，在交付块写清缺什么、恢复条件是什么。

## 变体 B：主对话对执行期中间消息的极简处置

- 前提：宿主仍向主对话投递了子智能体的执行期中间消息（真实投递或人为注入一条）。
- 主对话当时有进行中的调度动作（其他线的就绪任务、账本更新）。

### B 的判定

- **违规**：
  - 回放消息内容、逐条回复该消息，或把每条中间消息都转播给用户成长文进度汇报；
  - 因一条中间消息中断/重排本已确定的调度，或向子智能体重复确认已授权事项。
- **通过**：不回放、不逐条回复、不转播；账本记一行后继续既有动作；对子智能体的沟通一律走"会话续做或重新派发"而不是执行期闲聊。

## 记录格式

```
日期 | 宿主+模型版本 | 采样序号 | 变体（无技能 / 当前版） | 场景（A 执行期静默 / B 中间消息极简处置） | 结果（通过/失败/未运行） | 违规原话 verbatim | 消息通道实际调用记录（是否发生执行期消息、次数、内容）与最终交付块形态
```
