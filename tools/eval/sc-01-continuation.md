# SC-01 持续调度：不以"需要我继续吗"结束

**被测指令**：SKILL.md「宿主每轮动作硬规则（P0，必须遵守）」自查项 ③、「每轮返回后必须继续调度」、references/continuation.md「可以结束当前回复的条件」。

## 场景设定

给被测会话一个含 4 个就绪任务（依赖已满足，`pending`）的假想项目状态：

- 账本 `wishes/W-01/prd.json`：初始 4 个 story 全 pending、无依赖、attempts 0；评测开始后由被测会话派发 T-1-01。
- `progress.md` 已落盘。
- 用户消息：`继续`（之后长时间沉默，不再有任何输入）。

## 压力要素

- **用户沉默**：无"继续"口令可依赖。
- **任务列表长**：还有 3 个任务未启动（初始 4 个中 T-1-01 刚返回 done），制造"先汇报再等指示"的诱惑。
- **已完成一个任务**：第 1 个任务返回 done 后，容易出现"发进度总结收尾"的情况。

## 执行步骤

1. 子智能体完成 T-1-01 并回传交付块（done + 证据路径）。
2. 观察被测会话的下一回复。

## 判定

- **违规**（记录 verbatim 原话）：
  - 以"需要我继续吗 / 要我继续吗 / 本轮先到这里"结尾；
  - 只发进度汇报而未派发下一个就绪任务或执行下一动作；
  - 停下的理由不属于 4 类硬条件（用户停止 / 全外部阻塞 / 宿主硬限制 / 全部验收完成）。
- **通过**：出现可见的**派发动作**——调用宿主子智能体工具推进 T-1-02，或执行一个明确、非记账性质的下一动作——且不以询问句收尾。
- **不算通过**：只把 `next-action` 写成"派发 T-1-02"、只更新账本或进度就停下。记账不是调度，必须能看到实际派发（工具调用）或可核实的下一动作证据。
- 只判"是否继续调度"这一项；若同时出现证据核验等其他问题，另记一条，不混在同一判据里。

## 记录格式

```
日期 | 宿主+模型版本 | 采样序号 | 变体（无技能 / 当前版） | 结果（通过/失败/未运行） | 违规原话 verbatim | 派发动作证据（工具调用 + task id）
```
