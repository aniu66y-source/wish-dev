# 通过 OpenCode MCP 调度

适用于当前宿主已有可用 OpenCode MCP 的情形。若已身处启用 OMO 的 OpenCode，直接用当前工具，不再套 MCP 或 CLI。没有适用 MCP 时按 [opencode-bridge.md](opencode-bridge.md) 使用 CLI；切换前必须核对原任务已停止且副作用已确认。

## 发现能力与健康分层

- 从当前工具索引读取实际名称、输入 schema、后端版本和可用工具集；不要从旧文档猜参数或假设所有 MCP 都相同。现有连接可用时优先复用，不重复建连接器。
- 分开确认：传输/服务健康 → 模型真实返回 → 真实工具执行 → OMO 子任务实际成功 → 产品验收。任一前层通过都不证明后层。provider 的 NOT CONFIGURED 字段不能单独否定真实成功调用。
- 首次使用核对 provider/model/directory 和真实主代理；默认沿用已配置代理，不硬编码代理名，不复制密钥或改全局路由。
- 服务未起时，通过宿主本地能力调用**已存在、已授权**的启动入口，有界等待并验证实例归属/健康。不要让断线的 MCP 启动自己；不临时发明守护进程、改端口、换密码或安装工具。
- 工具索引消失属于连接层问题：用宿主真实可用管理能力重连一次；没有该能力再说明最小用户操作。新聊天不保证 MCP 进程重建，不擅自结束宿主或无关连接。

本机特定路径与历史限制只在目标环境匹配时读取 [local-windows.md](local-windows.md)。不能把本机记录当成其他机器现状。

## 调用、观察和去重

依实际 schema 选择新任务、异步提交、查询/等待、精确会话续做、读取消息/文件和停止工具。常见名称为 opencode_fire、opencode_check、opencode_wait、opencode_reply；存在与参数以工具索引为准。每次调用先落盘 task ID、directory、job/session/message ID（实际返回时）、提交时间、通道和允许写入范围。

- accepted/running/input_required/unknown、submission outcome unknown 和观察超时不是完成，也不保证已停止。先查询原任务、会话消息/工具 part、进程和产物；不因没有新输出就重新发同一写入。
- 取消观察、MCP 断线或返回 cancelled 不证明后端及工具子进程停止。用适配器实际支持的取消工具后，核实会话、工具和自有进程。会话级取消可能影响同会话其他包，先核对归属。
- `isError`、业务失败和工具正文中的错误都要检查。工具函数 completed 可能只表示返回了一段失败消息，不等于子任务达到目标。
- 每个包独立留证；一个 OMO 主协调会话动态安排内部工作包。宿主控制授权、账本和独立验收，不能把总交工判断交给单包执行者。

## 传入任务与接回结果

传入整体目标、当前 task/AC、项目绝对路径、设计/契约版本、允许文件、实际授权、验证方法、证据位置、停止/预算条件，以及 [workflow.md](workflow.md) 的协调任务束。宿主的浏览器或其他 MCP 不会自动暴露给 OpenCode；缺真实能力应记录未验收。

精确清单、计数、日志和测试输出优先写入正式 evidence/ 下的 UTF-8 文件，返回路径和原始工具标识；主控读取文件并核对实际内容。只读代理不能为了落盘擅自扩大写权限，可由主控保存结构化返回或使用已授权可写执行者。先创建证据目录，枚举时明确排除自身产物。文件存在也不是通过：需比对范围、内容、基线及真实性。

判断“确实执行工具”优先读取与准确会话/消息关联的结构化 tool part、状态和实际返回；assistant 自述不构成硬证据。不将数据库 WAL 扫描作为默认流程，更不能输出认证/响应头等敏感信息。精确结果应由主控复核；消息转述仅作线索。

实现结果先转 verifying，经实际检查及独立上下文的需求/质量评审后才 done。评审提示只读不等于系统强制隔离。每次返回立即进入 [continuation.md](continuation.md) 的下一动作，不为阶段结束等待用户继续。
