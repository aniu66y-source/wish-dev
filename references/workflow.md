# 执行记录、任务包与后端任务束

## 状态与真相来源

每轮临时资源使用独立 <runtime>/<project-slug>/<task-id>/<run-id>/，本机运行根为 E:\Claude Agent，桥接可通过参数或 WISH_DEV_RUNTIME_ROOT 指定。正式账本和有效证据保存在 wishes/<wish-id>/ 或项目既有位置；运行目录只存临时日志和工作副本，不作为唯一验收依据。结束前将必要脱敏结果归档并修正引用。优先更新已有记录，避免多套真相来源。

**账本落盘硬门禁**：派发首个子智能体任务前，`wishes/<wish-id>/` 下须同时存在 `prd.json` 与 `progress.md`；`check-plan.mjs` 在结构校验后检查同目录 `progress.md`，缺失即 `exit 2` + `ledger:false`（见 [plan-contract.md](plan-contract.md) 账本门禁节）。账本未落不进入产品实现。

最低字段：

~~~text
task-id / project / original-wish / delivery-target / acceptance-scope
requirement-version / design-version / contract-version / source-baseline
authorized-scope / forbidden-actions / assumptions / decisions / risks
user-dirty-files / owned-files / phase / packages / dependencies
acceptance-items / actual-checks / evidence-paths
subagent-task-ids / subagent-session-ids / transport / running-task-ids / owned-process-ids
release-version / target-environment / deployed-artifact / runtime-entry
quality-findings / required-remediation / review-status
attempts / no-progress-count / root-cause / same-cause-failures / resume-condition
last-change / concrete-next-action / blocker / handover-status
~~~

包状态：pending / running / verifying / done / blocked，机器契约见 [plan-contract.md](plan-contract.md)。pending 只有依赖 done 才可领取，verifying 表示实现已返回、待验收；不要同时维护两套活跃状态。整体状态：active / needs-user / interrupted / ready-for-acceptance / delivered。

阶段或包完成只更新该阶段/包；整体 delivered 由协调者对照完整交付目标决定。用户要求人工签收而尚未收到时，保持待签收，不能伪造确认；不需要签收的任务可以在证据完整后技术交工。CLI 返回码不决定整体状态。每轮返回后按 [continuation.md](continuation.md) 直接执行下一动作，不以进度汇报结束仍可执行的工作。

## 任务编号（并行线标识）

规划时**分离模块、多线并行**以提高交付速度。每条并行线用独立任务编号 **`T-<线>-<序号>`**（如 `T-2-01` = 第 2 线第 1 任务）标识，避免交接漂移：

- 同批号（同 `<线>`）的任务**可并行**；跨线任务靠"依赖"字段表达先后。
- 前置任务未 `done` 时，依赖它的下游任务不开始。
- 主对话据此判断"哪些线现在能领"，不逐条问用户。

**2 条调度硬规则（契约本身替代不了）：**

1. **共享契约唯一写入人**：公共接口、数据模型、依赖清单、锁文件、迁移顺序由一条指定"集成线"独占写入，其余线只读引用。这是避免交接漂移的真正关键，比任何字段都重要。
2. **任务编号 = 并行线标识**：`<线>` 是并行维度，`<序号>` 是线内顺序。跨线依赖显式写在"依赖"字段，不靠隐式约定。

## 子智能体任务下发契约（主对话 → 执行子智能体）

主对话把任务下发给宿主可派生的子智能体（默认 `general-purpose` 或等价执行体）。下发块用下方 12 项，全部填实际内容或后端可读取的绝对路径，不传"帮我开发"或不可访问的聊天引用：

~~~markdown
# T-2-01：具体目标
任务编号：T-2-01（T-<线>-<序号>）
任务目标：一句话说清本任务要交付什么。
任务背景：为什么做、承接哪条线、相关 AC 编号。
执行范围：允许触碰的模块/文件/接口边界。
依赖：前置任务编号（T-1-03 等）；无则写"无"。依赖未 done 不开始。
允许写入文件：本任务可写的文件清单/通配（独占归属）。
禁止写入：共享契约、锁文件、其他线文件（唯一写入人=集成线）。
执行要求：沿用的统一模块/状态来源、结构清理边界、代码质量指引路径。
限制条件：授权边界、费用、外部操作、凭据，不超范围。
交付要求：具体产物、必要测试和集成材料。
验收标准：可观察结果 + 证据方法（跑哪条命令、看哪个路径）。
优先级：高/中/低（同级内靠"依赖"排序）。
~~~

**下发附加字段（主对话随块带上，不计入 12 项）：**
- 修复预算：默认 3 次；耗尽或 3 次同根因 → 回主对话标 `blocked`。
- 子智能体 ID/会话 ID：派发后登记，续做用。

优先先稳定必要共享契约（集成线），再并行处理独立设计/模块/测试与部署准备，持续集成完整纵向链路。设计/架构任务也可依赖只读调查；外部服务和生产变更不因任务领取而自动获授权。

## 子智能体任务交付契约（执行子智能体 → 主对话）

执行子智能体完成后，**只回传下方结构化交付块 + 证据文件路径**，不回放执行日志/事件/中间产物给主对话：

~~~markdown
# T-2-01 交付
任务编号：T-2-01
任务状态：done / verifying / blocked / partial
完成内容：实际交付了什么（结论，非执行流水）。
修改内容：改了什么、影响哪些文件（定位用，非逐行）。
根因及解决方案：如涉修复，根因 + 采用的修法。
是否引入新结构问题/补丁堆积：有 → 列位置；主对话评审前必须关闭。
验证结果：跑的命令 + 摘要（非全量日志）。
证据路径：绝对路径（evidence/ 下），与"产物"分离，供主对话抽查。
遗留问题：本次范围内没解决的、有据的遗留。
未完成事项：本任务没做完的项 + 原因。
交付文件 / 路径：产物与运行入口的绝对路径。
需要主智能体处理的事项：需主对话或用户决策/授权的最小项。
其他说明：授权变化、依赖变化、恢复条件等。
~~~

- **状态 4 态对齐账本**：`done`（已验收）/ `verifying`（实现已返回、待主对话验收）/ `blocked`（修复预算耗尽或外部条件缺，附恢复条件）/ `partial`（部分完成，列未完成事项）。不另造"已完成/未完成"口语态。
- `done` 须附非空证据路径 + 独立评审（另一子智能体）的 spec/quality 通过；只读提示词不等于系统隔离。
- 主对话读交付块后**抽查证据文件**再更新账本；子智能体回报不自动等于事实。
- 下发单个任务时仅回传该任务状态及证据，不让子智能体自行判定整体交工。

首次可只读探测。已有足够接入证据和授权则直接推进，无需重复探测或询问是否继续。

## 需求、变更与验收追踪

~~~text
AC-ID | 需求/交付结果 | 设计/契约 | 工作包 | 验证环境/操作 | 结果 | 证据 | 限制
变更ID | 用户原话/依据 | 受影响需求/设计/包 | 时间/费用/发布影响 | 决策/授权 | 更新版本
风险ID | 触发条件 | 影响 | 处置/恢复 | 负责人 | 当前证据与状态

~~~

结果使用 passed / failed / not-run / not-applicable。not-applicable 要说明原因；不能把用户明确要求的验收项自行标不适用。整体交工前必须项不能仍为 failed 或 not-run。

## 阶段续做

续做任务束须保留整体交付目标、最新设计/契约/授权变化、已通过及未通过验收、
上轮实际产物、失败根因与下一步。发布中断时额外核对线上版本、迁移状态和流量，
不直接重跑可能已部分成功的操作。真实状态优先于旧摘要。

恢复前核对绝对项目路径、Git 分支/HEAD（存在时）、未提交改动、任务通道及准确 job/session ID；检查仍可能写入的进程。每次验收记录相关源文件 SHA-256 和检查入口/配置指纹；有未提交改动时不能只记 HEAD，非 Git 项目用文件指纹。只核对受影响范围，不为无关变化强制全量重测或提交用户文件。

基线变化、需求变化或整体失败时，先确认受影响写入停止；无法确认则阻塞冲突调度。保留旧证据历史，撤销当前失效 review/evidence 引用；原 task 转 pending（需改实现）或 verifying（仅重验且依赖已 done）。受影响下游在前置重新通过前回 pending；仍在写入的任务保留真实运行状态，不假装已回退。同步更新后重跑门禁，原 ID 和累计尝试数不变。缺可比较基线时先补验证，不继承旧 done。

整体验收发现缺陷也回原任务、原 AC 和原修复预算，复现后修复/复审受影响链路。只有确属新增范围才新建包，记录范围和预算影响；不能靠拆包、改 ID 或另开最终修复轮逃避熔断。

## 卡点主动联网

遇无法解释的错误、版本/API 不确定、合理修复仍失败、重复错误或只能临时绕过时：

1. 保存原始现象、最小复现、版本、退出码和已排除假设；去掉凭据、响应头和敏感项目内容。
2. 先核对当前官方文档、源码及上游 Issue/PR；补充社区经验时检查日期、适用版本和可复现条件。
3. 比较候选的根因吻合、兼容性、风险和维护成本，不以搜索排名/热度决定，也不盲跑网络命令。
4. 选择证据最充分且贴需求的最小合理修复，有必要时在隔离临时目录做有界实验，再回归原失败场景和受影响路径。
5. 记录来源、采用/舍弃理由、真实结果与剩余不确定。已有足够证据停止漫游；调查/下载计入时间成本，不当作无限预算。

修复及同根因/无进展计数按 [plan-contract.md](plan-contract.md) 持久保存。网络不可用、权限/渠道拒绝如实记录；继续可独立完成工作，不通过换客户端伪装或换工具绕过限制。

## 临时资源与进程收尾

创建时在 progress.md 登记：task/run ID、时间、精确绝对路径或 PID、进程启动时间/可执行文件/父子归属、用途、是否共享、保留和清理条件。不要登记含凭据的完整命令行。临时目录置于用户运行根下独立子目录，不能把整个 E:\Claude Agent、项目或全局缓存登记成一次性目录。

1. 先核对相关 job/会话已完成或确实停止，以及后续验证/用户预览是否仍需要资源。unknown、观察超时、取消已请求都不算停止；可能仍写入时不删。失败/阻塞时保留最小诊断和恢复必要信息，释放其他已无依赖资源。
2. 停本轮自建且不再需要的开发/测试进程，优先正常退出；必要时逐 PID 再核启动时间、exe 和父子归属，防止 PID 复用。不按 node/powershell 等名字批量杀，不停其他项目、宿主或交付需要的运行入口。
3. 宿主子智能体运行框架、常驻服务与仍使用的工具缓存属于共享设施，普通交工不停止/删除。只有本轮隔离且能证明独占、无运行或未知任务、无交付依赖的进程/实例才有序停止；共享服务维护另按用户授权。
4. 将必要脱敏结果、截图、诊断归档至正式 evidence/ 并修正引用；再删本轮登记且不再需要的下载、一次性脚本副本、夹具和纯调试输出。保留源代码、锁文件、交付物、有效证据、原始数据、凭据及现有用户文件；未登记旧缓存不顺带清理。
5. 删除前解析绝对路径，确认它在本轮允许临时根内且不是根本身。检查目标和祖先的符号链接/联接点；递归时在不跟随链接的前提下逐层检查子项。发现链接、无法证明范围或归属时跳过并报告，不能跟随到项目数据。Windows 用同一 PowerShell 的 LiteralPath 等原生操作，不跨 shell 拼接路径，不使用无范围递归或 git clean/reset。
6. 核对文件移除、进程退出和适用端口释放，追加真实结果。失败保留原因，不把“请求过”当完成；不以收尾改变代码验收结论。登记资源的常规释放按任务授权执行，不逐项再索要继续口令；扩大删除范围则另核授权。
