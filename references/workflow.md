# 执行记录、任务包与交付契约

## 状态与真相来源

每轮临时资源使用独立 <runtime>/<project-slug>/<task-id>/<run-id>/；<runtime> 由 `WISH_DEV_RUNTIME_ROOT`、显式参数或用户指定目录决定，不写进项目或全局缓存。正式账本和有效证据保存在 wishes/<wish-id>/ 或项目既有位置；运行目录只存临时日志和工作副本，不作为唯一验收依据。结束前将必要脱敏结果归档并修正引用。优先更新已有记录，避免多套真相来源。

**账本落盘硬门禁**：派发首个子智能体任务前，`wishes/<wish-id>/` 下须先有草稿 `prd.json` 与含连续 5 字段表头的 `progress.md`（表头窗口、可接受写法与失效判定一律见 [plan-contract.md](plan-contract.md)「账本落盘硬门禁」节，此处不重复口径）；`check-plan.mjs` 在结构校验后检查同目录 `progress.md`，缺失即 `exit 2` + `ledger:false`，表头不成立同样拒绝。调研证据尚未取得时门禁非零属预期：可先派只读调研子智能体，补齐证据后复跑门禁，通过才进产品实现。

记账字段（主对话维护，非机器门禁；门禁只强制 5 字段表头，见 [plan-contract.md](plan-contract.md)）：

~~~text
task-id / project / runtime_root / original-wish / delivery-target / acceptance-scope
requirement-version / design-version / contract-version / source-baseline
base-commit / baseline-snapshot / review-material-path
authorized-scope / forbidden-actions / assumptions / decisions / risks
user-dirty-files / owned-files / phase / packages / dependencies
acceptance-items / actual-checks / evidence-paths
subagent-task-ids / subagent-session-ids / transport / running-task-ids / owned-process-ids
release-version / target-environment / deployed-artifact / runtime-entry
quality-findings / required-remediation / review-status
attempts / no-progress-count / root-cause / same-cause-failures / resume-condition
last-change / concrete-next-action / blocker / handover-status
~~~

包状态：pending / running / verifying / done / blocked，机器契约见 [plan-contract.md](plan-contract.md)。pending 只有依赖 done 才可领取，verifying 表示实现已返回、待验收；不要同时维护两套活跃状态。整体状态：active / needs-user / interrupted / ready-for-acceptance / delivered。`transport` 记录**执行通道**：`subagent`（宿主子智能体）/ `subtask`（宿主提供的隔离子任务）。`subtask` 只有在能执行工具、拥有独立上下文、任务可追踪、可用于独立评审时才算等价通道；普通函数调用、共享上下文步骤或仅名字叫 subtask 的不算，见 [portability.md](portability.md) 能力前提。同步/异步属于**运行模式**（记在任务备注并关联 `running-task-ids`），不塞进本字段；`team-teammate` 仅为历史兼容，本技能不使用。

阶段或包完成只更新该阶段/包；整体 delivered 由协调者对照完整交付目标决定。用户要求人工签收而尚未收到时，保持待签收，不能伪造确认；不需要签收的任务可以在证据完整后技术交工。CLI 返回码不决定整体状态。每轮返回后按 [continuation.md](continuation.md) 直接执行下一动作，不以进度汇报结束仍可执行的工作。

## 任务编号（并行线标识）

规划时**分离模块、多线并行**以提高交付速度。每条并行线用独立任务编号 **`T-<线>-<序号>`**（如 `T-2-01` = 第 2 线第 1 任务）标识，避免交接漂移：

- **编号即账本 id**：`prd.json` 的 `stories[].id` 与下发块「任务编号」、交付块、`depends_on` 用同一字符串（如 `T-2-01`），不维护第二套编号，避免交接时翻译出错。
- 同一条线（同 `<线>`）的任务**可并行**；跨线任务靠"依赖"字段表达先后。
- 前置任务未 `done` 时，依赖它的下游任务不开始。
- 主对话据此判断"哪些线现在能领"，不逐条问用户。

**2 条调度硬规则（契约本身替代不了）：**

1. **共享契约唯一写入人**：公共接口、数据模型、依赖清单、锁文件、迁移顺序由一条指定"集成线"独占写入，其余线只读引用。这是避免交接漂移的真正关键，比任何字段都重要。
2. **任务编号 = 并行线标识**：`<线>` 是并行维度，`<序号>` 用于线内编号，不自动建立先后关系。线内与跨线依赖都显式写在 `depends_on`，不靠编号推断。

## 子智能体任务下发契约（主对话 → 执行子智能体）

主对话把任务下发给宿主可派生的子智能体（默认用通用执行型子智能体，常见类型名 `general-purpose`），**逐线以独立子智能体派发，不用团队队友模式**（不组队、不让子智能体互发消息或向主对话发执行期消息、不共享团队任务列表、不在队友间转派；跨线协调只走主对话，见 SKILL.md 总纲「主对话边界（P0，领导层）」的「调用契约」段）。下发块用下方 12 项，全部填实际内容或后端可读取的绝对路径，不传"帮我开发"或不可访问的聊天引用：

~~~markdown
# T-2-01：具体目标
任务编号：T-2-01（T-<线>-<序号>）
任务目标：一句话说清本任务要交付什么。
任务背景：为什么做、承接哪条线、相关 AC 编号。
执行范围：允许触碰的模块/文件/接口边界。
依赖：前置任务编号（T-1-03 等，与 prd.json 的 `stories[].id` 同一串）；无则写"无"。依赖未 done 不开始。
允许写入文件：本任务可写的源码与正式文档清单/通配（独占归属，即 `allowed_files`）。
禁止写入：共享契约、锁文件、依赖清单、迁移顺序及其他线文件（唯一写入人=集成线任务）；需求/设计/评审等正式产物与证据、临时输出的写入权限见 [plan-contract.md](plan-contract.md)「写入权限（三类）」。只读调查或仅向证据目录输出方案的任务写 `read_only: true`、`allowed_files: []`，并把要读的范围写成 `read_scope`（只读，不授予写权）。
执行要求：沿用的统一模块/状态来源、结构清理边界、代码质量指引路径。
限制条件：授权边界、费用、外部操作、凭据，不超范围。
交付要求：具体产物、必要测试和集成材料。
验收标准：可观察结果 + 证据方法（跑哪条命令、看哪个路径）。
优先级：高/中/低（同级内靠"依赖"排序）。
~~~

**下发附加字段（主对话随块带上，不计入 12 项）：**
- 运行模式：按宿主能力选择，不写死。宿主支持在一条消息里批量同步派生时，可对多条独立线并行同步调用；支持异步派生（后台任务）时，可把独立任务放异步通道并行推进，再用结果读取接口有界取回。小任务、强耦合或共享写入的任务串行，不为并行而并行。无论哪种模式都要登记准确 task/会话 ID、结果可追踪、未知写入不重复派发；需要追问时用会话续做或重新派发并附上下文文件。不写死并行个数、宿主工具名或等待时长。
- 执行期静默：随块告知子智能体——执行期间不向主对话发送任何中间消息、进度或汇报，中间产出写证据/运行根文件；唯一回传 = 任务结束时的结构化交付块 + 证据路径；需要决策或授权时按 `blocked`/`partial` 语义结束并在交付块写恢复条件，不发消息驻留等待。
- 修复预算：默认 3 次（写进 `budget.max_fix_attempts`，字段必填、无内置兜底）；耗尽、连续 3 次无进展或 3 次同根因 → 回主对话标 `blocked`（计数按 [plan-contract.md](plan-contract.md) 持久保存）。
- 子智能体 ID/会话 ID：派发后登记，续做用。
- 模型档位：遵守宿主能力、项目规则与用户预算；允许选模型时，按任务复杂度、风险和实际表现选择。规格明确的机械工作可选较低成本模型，复杂架构与高风险评审优先能力更强的可用模型，不要求所有评审使用最高档。省略参数时的继承行为以实际宿主为准，不假定继承最贵模型。修复停滞先查根因；有模型能力不足的证据才考虑升档，权限、环境或需求错误不靠升档解决，超预算须先取得授权。
- 大块工件走文件：完整任务书、接口细节或长上下文落运行目录文件，下发块只带**绝对路径 + 一行说明**，不把整段内容贴进派发 prompt；后续派发不层层累积历史任务摘要——子智能体需要的是本任务、相邻接口与全局约束，不是会话编年史。

优先先稳定必要共享契约（集成线），再并行处理独立设计/模块/测试与部署准备，持续集成完整纵向链路。设计/架构任务也可依赖只读调查；外部服务和生产变更不因任务领取而自动获授权。

## 子智能体任务交付契约（执行子智能体 → 主对话）

执行子智能体执行期间保持静默，不向主对话发送任何中间消息/进度/汇报（见 SKILL.md「调用契约」执行期静默）；任务结束时**只回传下方结构化交付块 + 证据文件路径**，不回放执行日志/事件/中间产物给主对话：

~~~markdown
# T-2-01 交付
任务编号：T-2-01
任务状态：done / verifying / blocked / partial
完成内容：实际交付了什么（结论，非执行流水）。
修改内容：改了什么、影响哪些文件（定位用，非逐行）。
根因及解决方案：如涉修复，根因 + 采用的修法。
是否引入新结构问题/补丁堆积：有 → 列位置；主对话评审前必须关闭。
验证结果：跑的命令 + 摘要（非全量日志）。
证据路径：指向 `evidence/` 内文件的绝对路径，与"产物"分离，供主对话抽查。
遗留问题：本次范围内没解决的、有据的遗留。
未完成事项：本任务没做完的项 + 原因。
交付文件 / 路径：产物与运行入口的绝对路径。
需要主智能体处理的事项：需主对话或用户决策/授权的最小项。
其他说明：授权变化、依赖变化、恢复条件等。
~~~

- **交付块状态与账本映射**：`done`（已验收）/ `verifying`（实现已返回、待主对话验收）/ `blocked`（修复预算耗尽或外部条件缺，附恢复条件）/ `partial`（部分完成，列未完成事项）。不另造"已完成/未完成"口语态。
- **`partial` 的账本映射**：账本状态仍是上方五态之一，不新增机器状态——仍有未完成工作则保持 `running`/`verifying`，需重领实现则回 `pending`；未完成事项与原因记入 `progress.md`，主对话核对应记哪态后更新。
- `done` 须附非空证据路径 + 独立评审（另派新实例、不复用实现者会话）的 spec/quality 通过；只读提示词不等于系统隔离。
- **独立评审的输入走文件**：评审子智能体拿到的是任务下发块 + 交付块 + **评审材料**。派发实现前记录基线（`BASE`、HEAD/索引/工作区/未跟踪各层摘要、写入范围），用 `node "<skill>/scripts/review-material.mjs" snapshot --repo "<repo>" --out "<runtime>/baseline-T-x-y.json" --scope "src/**,test/**"`，其中路径与 scope 替换为本任务实际值，scope 用逗号分隔字符串而非 `allowed_files` JSON 数组；评审前用同一脚本 `collect --snapshot "<runtime>/baseline-T-x-y.json" --repo "<repo>" --out "<runtime>/material-T-x-y.md"` 生成材料。材料落文件不贴正文；材料为空且无其他产物/证据时不得派评审，评审者不空评。覆盖哪些层、如何按层归属、范围语义、完整性口径与输出路径边界一律见 [plan-contract.md](plan-contract.md)「评审材料与基线」，此处不重复表述。
- **证据路径两套写法**：交付块里写**绝对路径**方便主对话抽查；写进 `prd.json` 的 `evidence` 必须是愿望目录下的**相对路径**（`evidence/…`），两者不要混用。
- 主对话读交付块后**抽查证据文件**再更新账本；子智能体回报不自动等于事实。
- 下发单个任务时仅回传该任务状态及证据，不让子智能体自行判定整体交工。

首次可只读探测。已有足够接入证据和授权则直接推进，无需重复探测或询问是否继续。

## 需求、变更与验收追踪

~~~text
AC-ID | 需求/交付结果 | 设计/契约 | 工作包 | 验证环境/操作 | 结果 | 证据 | 限制
变更ID | 用户原话/依据 | 受影响需求/设计/包 | 时间/费用/发布影响 | 决策/授权 | 更新版本
风险ID | 触发条件 | 影响 | 处置/恢复 | 负责人 | 当前证据与状态
审查ID | 位置/结构原因/影响 | 处置与负责人 | 必须整改/非阻塞 | 验证与复审结果
~~~

结果使用 passed / failed / not-run / not-applicable。not-applicable 要说明原因；不能把用户明确要求的验收项自行标不适用。整体交工前必须项不能仍为 failed 或 not-run。

## 阶段续做

续做任务束须保留整体交付目标、最新设计/契约/授权变化、已通过及未通过验收、
上轮实际产物、失败根因与下一步。发布中断时额外核对线上版本、迁移状态和流量，
不直接重跑可能已部分成功的操作。真实状态优先于旧摘要。

恢复前核对绝对项目路径、Git 分支/HEAD（存在时）、未提交改动、任务通道及准确 job/session ID；检查仍可能写入的进程。每次验收记录相关源文件 SHA-256 和检查入口/配置指纹；有未提交改动时不能只记 HEAD，非 Git 项目用文件指纹。只核对受影响范围，不为无关变化强制全量重测或提交用户文件。

基线变化、需求变化或整体失败时，先确认受影响写入停止；无法确认则阻塞冲突调度。保留旧证据历史，撤销当前失效 review/evidence 引用；原 task 转 pending（需改实现）或 verifying（仅重验且依赖已 done）。受影响下游在前置重新通过前回 pending；仍在写入的任务保留真实运行状态，不假装已回退。同步更新后重跑门禁，原 ID 和累计尝试数不变。缺可比较基线时先补验证，不继承旧 done。

整体验收发现缺陷也回原任务、原 AC 和原修复预算，复现后修复/复审受影响链路。只有确属新增范围才新建包，记录范围和预算影响；不能靠拆包、改 ID 或另开最终修复轮逃避熔断。

## 卡点主动联网

遇无法解释的错误、版本/API 不确定、合理修复仍失败、重复错误或只能临时绕过时：

1. 保存原始现象、最小复现、版本、退出码和已排除假设；去掉凭据、响应头和敏感项目内容。
2. 先核对当前官方文档、源码及上游 Issue/PR；补充社区经验时检查日期、适用版本和可复现条件。
3. 比较候选的根因吻合、兼容性、风险和维护成本，不以搜索排名/热度决定，也不盲跑网络命令。
4. 选择证据最充分且贴需求的最小合理修复，有必要时在隔离临时目录做有界实验，再回归原失败场景和受影响路径。
5. 记录来源、采用/舍弃理由、真实结果与剩余不确定。已有足够证据停止漫游；调查/下载计入时间成本，不当作无限预算。

修复及同根因/无进展计数按 [plan-contract.md](plan-contract.md) 持久保存。网络不可用、权限/渠道拒绝如实记录；继续可独立完成工作，不通过换客户端伪装或换工具绕过限制。

## 临时资源与进程收尾

创建时在 progress.md 登记：task/run ID、时间、精确绝对路径或 PID、进程启动时间/可执行文件/父子归属、用途、是否共享、保留和清理条件。不要登记含凭据的完整命令行。临时目录置于用户运行根下独立子目录，不能把整个运行根、项目或全局缓存登记成一次性目录。

可重定向的包/构建/下载缓存（npm、pip、go、cargo 等）统一指向本轮运行根内的缓存子目录，使归属可界定、可安全清理；不可重定向的保持宿主默认，归入下方第 3 条共享设施，收尾只登记不动。运行根实际路径在会话开始时固化进 progress.md 的 `runtime_root` 字段，主对话与各子智能体共用同一落点，避免各自推断。

1. 先核对相关 job/会话已完成或确实停止，以及后续验证/用户预览是否仍需要资源。unknown、观察超时、取消已请求都不算停止；可能仍写入时不删。失败/阻塞时保留最小诊断和恢复必要信息，释放其他已无依赖资源。
2. 停本轮自建且不再需要的开发/测试进程，优先正常退出；必要时逐 PID 再核启动时间、exe 和父子归属，防止 PID 复用。不按 node/powershell 等名字批量杀，不停其他项目、宿主或交付需要的运行入口。
3. 宿主子智能体运行框架、常驻服务与仍使用的工具缓存属于共享设施，普通交工不停止/删除。只有本轮隔离且能证明独占、无运行或未知任务、无交付依赖的进程/实例才有序停止；共享服务维护另按用户授权。
4. 将必要脱敏结果、截图、诊断归档至正式 evidence/ 并修正引用；再删本轮登记且不再需要的下载、一次性脚本副本、夹具和纯调试输出。保留源代码、锁文件、交付物、有效证据、原始数据、凭据及现有用户文件；未登记旧缓存不顺带清理。
5. 删除前解析绝对路径，确认它在本轮允许临时根内且不是根本身。检查目标和祖先的符号链接/联接点；递归时在不跟随链接的前提下逐层检查子项。发现链接、无法证明范围或归属时跳过并报告，不能跟随到项目数据。Windows 用同一 PowerShell 的 LiteralPath 等原生操作，不跨 shell 拼接路径，不使用无范围递归或 git clean/reset。
6. 核对文件移除、进程退出和适用端口释放，追加真实结果。失败保留原因，不把“请求过”当完成；不以收尾改变代码验收结论。登记资源的常规释放按任务授权执行，不逐项再索要继续口令；扩大删除范围则另核授权。
