# 每轮返回后的继续执行协议

本协议约束协调者何时调用下一工具、何时可以结束当前回复。它不是守护进程、定时器或无限重试授权。保持同一项目、愿望 ID、账本和 OMO 主会话；分包数量动态，修复预算有界。

## 工作循环

每次工具/CLI/代理返回、阶段评审完成、用户只询问进度或上下文恢复后：

1. **归档本轮事实**：核对产物、原任务 ID、后台状态和完整工具证据；更新 progress.md 和当前计划。消息“完成”、退出码 0、accepted、观察超时都不直接标 done。
2. **检查剩余工作**：对照整体目标、AC、依赖、实际授权和文件归属。门禁结构通过时读取 next_actions，结合真实状态决定调度；该列表是候选动作，不表示全部同时启动。
3. **执行下一动作**：有授权且无冲突的就绪工作，直接调用下一工具。可以先给简短进度，但不能给结束本轮的最终回复后等用户说“继续”。长任务继续观察原 ID，已停止的会话按准确 session ID 续做。
4. **复核退出条件**：只在下述真实条件之一成立时结束；尚可独立执行的工作先做完。不要为了延长运行制造任务、变更范围、扩大预算或重复轮询已明确阻塞的接口。

| 当前事实 | 必须采取的下一动作 |
|---|---|
| 原调用 accepted/running/unknown 或观察超时 | 观察、查询原 job/session 和写入；不重派、不跨 MCP/CLI 另起写入 |
| 实现已返回、证据可查 | 转 verifying，核对需求和质量并做独立评审 |
| 评审失败或整体验收失败 | 回到原 task ID，撤回受影响验收，原预算内定位/修复/复验；不新建任务逃避失败 |
| 包通过 | 标 done 后检查计划，领取依赖已满足的下一包 |
| 一个包受外部条件或预算阻塞 | 记录恢复条件；继续不依赖它的调查、设计、实现、验证或交接 |
| 当前阶段完成 | 补齐下一阶段输入并执行，不把“阶段完成”当整体交工 |
| 全部包 done | 执行跨包集成和原始愿望的最终验收；缺必须项则回流，不直接宣布 delivered |

阶段尚未形成可运行 prd.json 时也按同一原则继续补齐调查/需求/设计；“还没有机器计划”不是等待继续口令的理由。静态维护/仅配置 Skill 时完成用户要求即结束，不自动启动产品开发。

## 可以结束当前回复的条件

- 约定交付目标及全部必须验收已满足，相关后台写入结束，交工和适用收尾完成。
- 用户明确要求停止、暂停或在某个边界交接。先保留检查点，尊重该边界。
- 所有剩余路径均缺必要用户决定、授权、凭据、外部设备/服务或已耗尽预算，已经完成所有独立工作。附最小具体缺项和恢复条件；不重复请求已有授权。
- 宿主硬时限、工具/额度硬限制或执行环境即将终止，客观无法继续。保存真实完成度、未完成 ID 和下一动作；不冒充项目完成。

同根因三次失败阻塞的是相关分支；不能据此停止整个尚有可行工作的项目，也不能无视熔断无限换措辞重试。合理进度更新不算结束条件。不要使用“本轮先到这里”“下一轮再做”“要我继续吗”结束仍有可执行工作的回复。

## 检查点与恢复

每轮及上下文将满前将下一项**具体动作**、输入文件/版本、准确主会话/任务 ID、权限/预算、运行写入、完成证据和阻塞落盘。恢复先读账本并核对文件/进程及验收基线，再直接继续；缺失 ID 时先调查，不猜最近会话。宿主会话内的自动压缩不重置失败计数。恢复前先确认 `progress.md` 已随 `prd.json` 落盘（账本门禁，见 [plan-contract.md](plan-contract.md)）；缺账本就回到 pending 补账本，不以"还没机器计划"为由跳过落盘。

Skill 能约束当前会话的行为，无法提高宿主额度、阻止软件关闭或在关闭后自我唤醒。未实际配置的调度/长期值守不得声称存在；不因“持续推进”擅自安装常驻循环或外发消息。
