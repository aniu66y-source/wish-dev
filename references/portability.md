# 安装、移植与能力边界

## 安装

本包采用 [Agent Skills 规范](https://agentskills.io/specification)：wish-dev/ 根目录下有 SKILL.md，资源以相对路径引用。

1. 软件支持 ZIP 技能导入时导入 wish-dev.zip。其他扩展名/封装要求以目标软件官方规则为准，不承诺所有软件直接导入 ZIP。
2. 通过目录发现技能的软件，把完整 wish-dev 文件夹复制到它配置的 skills 目录。不要只复制 SKILL.md。
3. 已有同名技能先比较，确认后备份/更新，不直接覆盖。
4. 确认技能可见，再发送具体愿望（自然语言即可，无需固定启动话术）；调用本技能即进入分工模式。

**安装宿主技能（把 skill 放入宿主 skills 目录）与宿主执行能力是两件事。** 宿主安装 skill 由用户或宿主完成；执行能力缺失（宿主可派生子智能体、模型工具调用、Node ≥ 18）按 [setup-bootstrap.md](setup-bootstrap.md) 检测与补齐，不覆盖用户既有配置。本技能不迁移既有配置、不写明文密钥。

## 能力要求

| 宿主能力 | 可完成工作 |
|---|---|
| 可派生子智能体 + 读文件 + 执行命令 + 读写授权项目 + 跟踪长任务 | 完整流程，执行下沉子智能体 |
| 只能读提示词，不能执行命令/派生子智能体 | 整理需求和计划，不能声称实际开发 |
| 云端不能访问本机路径 | 需要用户授权的远程执行通道 |

**硬前提**：宿主能派生子智能体（Agent / general-purpose 或等价可派生执行体），且模型支持工具调用。缺任一则无法分包并行执行，只能降级为整理需求/计划（见 [setup-bootstrap.md](setup-bootstrap.md) 开工硬门控）。

机器计划门禁需要 Node 18+，缺少时按 [setup-bootstrap.md](setup-bootstrap.md) 安装并复测，不手填 ok 当通过。沿用现有模型、认证和额度，不默认使用特定"免费"服务，不承诺无限 token 或无期限后台运行。

完整交付还需要目标宿主能访问相应设计/渲染、构建/测试及实际部署环境；根据项目形式使用已有工具，不假定安装技能就获得服务器、账号或发布权限。运行根目录由 `WISH_DEV_RUNTIME_ROOT` 或用户指定目录决定，移植时不需要改动技能源码。

## 使用与流程裁剪

示例：

> 使用 wish-dev（许愿式开发）：我想做一个……，给……使用，
> 核心流程是……，已有资料/项目在……，希望交付到……。
> 按现有约束自主完成产品梳理、选型、UI＋UE、架构、开发、测试、部署与交接；
> 先调查，只在关键业务或缺失授权确实需要我决定时再问。

用户无需预先给技术栈、完整 UI 或架构。已有足够需求就直接推进；缺少目标环境或凭据时先调查并完成其他独立工作，不要求用户一次回答全部技术细节。授权以实际对话和项目规则为准，示例本身不授予外部操作权限。

主文件说明完整流程与边界；当前阶段细节见 [lifecycle.md](lifecycle.md)，任务与子智能体契约见 [workflow.md](workflow.md)，实际发布和维护交接见 [release-handover.md](release-handover.md)。按规模合并步骤和文档，不以十二个环节强制十二份文档或十二轮批准。

## 兼容性验证

依次检查：技能可发现 → 资源可读 → 宿主可派生子智能体 → 实际派包并收集结果 → 功能验收。

前一层不证明后一层。不能把某宿主（如 Windows）的验证说成所有宿主或 Linux/macOS 已验证。
