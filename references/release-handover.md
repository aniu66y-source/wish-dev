# 部署、上线验证与维护交接

在调查阶段预览目标和前提；准备发布或交接时读取完整内容。按产品形式选择实际需要的步骤，不预设必须有云、域名、容器、数据库或持续值守。

## 交付目标与授权

确认是源码、本地程序、测试环境还是生产上线。用户明确要求部署时，将目标环境发布和上线验收列为必须交付；已有目标环境的批量授权时，按授权范围执行，不逐步重复批准。

优先调查已有配置、资源和文档。需要用户决定时提供具体目标、版本、将执行的动作、影响、费用、数据风险及恢复方案后再问。缺少目标、必要凭据或授权不代表可自行采购、创建账号、发布到个人账号或改为本地交工。

凭据通过现有安全机制接入，交付文档只给变量名、用途和获取方式，不保存明文秘密。按目标环境实际权限执行，不因发布方便而全局放权。

## 发布准备与执行

| 检查项 | 需要形成的事实或操作 |
|---|---|
| 版本与范围 | 关联源码基线、需求/验收版本、待发布内容，确认用户未提交文件的归属 |
| 构建/分发 | 使用可重复的命令生成可识别版本的产物，按需记录摘要；不打包密钥或无关文件 |
| 环境与配置 | 明确运行时、资源、网络、配置变量、依赖服务和启动方式，区分开发/测试/生产 |
| 发布路径 | 复用已有脚本/流水线；缺失时按规模提供可执行的部署或安装步骤并验证 |
| 数据与兼容 | 涉及迁移时确认顺序、兼容窗口和失败恢复；先在可用的非生产环境演练 |
| 备份与恢复 | 涉及已有重要数据时确认备份目标、时间和可恢复性；不能只以备份文件存在作证明 |
| 回退 | 明确旧版本、触发条件、执行方法与限制；区分应用回退、迁移回退和数据恢复 |
| 发布后检查 | 提前定义实际入口的健康及核心业务验证、日志/指标、失败处理和首轮观察边界 |

不适用项写明原因。发布工具/能力不足时先完成方案、产物及其他独立工作，说明最小缺项。

发布前审查最终差异、配置/资源目标和必要授权，按已经批准的方式部署，记录实际结果。发布失败可能是部分成功，先核对当前线上状态再恢复，避免重复迁移、重复创建资源或覆盖服务。

本地桌面/离线软件：验证约定机器/系统上的安装或解压、启动、数据保存与必要的分发/更新方式；未要求时不强行增加域名和云部署。
Web/服务：验证实际目标的应用进程、入口访问和真实业务，涉及域名、TLS、反向代理或后台任务时分别验证。
移动/商店等需签名/平台审核的交付：按用户要求处理实际渠道与权限；未完成的外部审核如实标明，不能冒充已上架。

## 上线验证与有界观察

- 对实际发布版本、环境和入口执行核心业务及适用的权限/数据/集成验证，不能仅检查首页或 HTTP 状态。
- 按风险检查重启、后台任务、日志、资源和外部连接；生产验证使用受控的测试数据和非破坏性路径。
- 设定与项目风险和预算相符的首轮观察边界及结束条件，发现影响验收的问题则修复/回退并重验。
- 不默认建立长期监控、告警外发或值守服务。用户另有要求时，核对授权、接收方、成本、运行条件与真实调度状态。
- 线上检查通过只证明实际执行的范围，不承诺长期无故障；记录可维护的运行方式及必要限制。

发布/运行记录：

~~~text
环境/目标 | 版本/产物 | 授权依据 | 实际发布动作/时间 | 迁移状态
实际入口 | 上线检查与结果 | 证据 | 初始观察结果 | 恢复/回退状态
~~~

## 最终交工包

按实际需求提供，优先复用项目现有说明：

- 对应版本的源码、构建/运行产物和实际入口，说明如何确认当前版本。
- 用户操作说明、角色/权限说明和核心流程。
- 开发/运行前提、启动/构建/测试命令、配置变量名及外部依赖。
- 需求验收矩阵：实际环境、行为、结果、证据、未执行项和剩余限制。
- 适用的部署/更新、数据迁移、备份恢复、回退和故障定位方法。
- 适用的资源/域名/证书/账号维护归属、持续费用与必要维护事项；不把秘密写进交付包。

接收者应能按说明使用，并具备后续维护所需的信息；不能只提供一段终端成功输出。

## 完成状态与最终汇报

整体交工先核对原始目标、所有必须验收及后台任务，不能只看最后工作包；确认 [code-quality.md](code-quality.md) 规定的本轮必须整改项已经修复、验证并复审。真实保留的临时措施须明确边界和清理条件。按实际情况汇报：

~~~markdown
完成状态：技术交工 / 待用户签收 / 整体受阻及已完成部分。
实际运行入口与版本：
源码、产物和说明位置：
必须验收结果及证据：
部署与首轮运行结果：按约定适用。
使用与维护入口：
剩余限制、外部待办、必要用户操作：仅列实际存在项。
~~~

只有约定交付层级与必须验收均满足才技术交工。用户要求人工签收时等待真实确认；
未要求时不另加签字门槛。关键设备/真实集成/发布缺失时如实标受阻，不以 mock 或
测试环境结果代替。范围内可独立工作应先完成，不能为等待签收而停下尚可执行的任务。
